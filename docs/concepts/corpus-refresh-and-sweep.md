# Corpus refresh and the nightly sweep

Two scheduled jobs keep a hosted Trailhead Rx honest without a person watching it.

**Refresh** (`trailheadrx refresh`, `src/trailheadrx/refresh.py`) re-fetches every source the site depends on and compares a *content fingerprint* — a SHA-256 of the visible text for HTML, of the bytes for PDF — with the last one it saw. A changed policy document is saved and re-indexed on the spot (the document's chunks and embeddings are removed and rebuilt; nothing else in the index moves). A changed maker program page is only reported, because the terms in `corpus/programs/manifest.yaml` are hand-verified and a person must re-read them. Every source gets a *checked-on* date, which the footer shows and the freshness guardrail (G6) treats as currency: "we looked last night and it had not changed" is a valid reason to trust an old effective date. Failures are reported once, not every night, so a site that blocks scripts does not become noise. The industry name for this pattern is a **content-hash change detector**; the job is **idempotent** — running it twice in a row does nothing the second time.

**Sweep** (`trailheadrx sweep`, `src/trailheadrx/precompute.py`) is **precomputation** plus a **regression check**. The form's menu is finite, so every menu-only request can be answered ahead of time through the same `compute()` the website runs; the results land in a disk-backed cache and a visitor gets them instantly. Each fresh answer's summary, numbered steps and lead-time months are compared with the previous sweep's; a difference when the underlying document did not change means the model read the same text differently, which is exactly what a human should look at. The sweep is budget-capped per night and can be limited to the most-asked pairs.

Both jobs are started by a GitHub Actions schedule that runs the command inside the live Fly machine over SSH, so they see the same index and disk the site does. Email goes through Resend only when there is something to say.
